# dota2-mcp — Обслуживание, обновление и отладка

Краткая шпаргалка: что делать при выходе обновления Dota, как обновить сам
сервер, и как дебажить, если что-то сломалось. Подробности по архитектуре — в
`DOCUMENTATION.md`.

Все пути ниже для Windows. `%TEMP%` = `C:\Users\<you>\AppData\Local\Temp`.

---

## 0. Подключать сервер только к нужным проектам

MCP-серверы в Claude Code имеют **scope** (область видимости). Это и есть способ
держать `dota2-mcp` только там, где он нужен.

- **`--scope project` (рекомендую для аддонов):** сервер прописывается в файле
  `.mcp.json` **в корне конкретного проекта**. Он доступен только когда открыт
  этот проект, и (если хочешь) коммитится в git, чтобы коллеги по аддону получили
  его автоматически. Заходишь в каждый аддон-проект, где нужен сервер, и делаешь:
  ```powershell
  cd C:\Users\Admin\Documents\project\rda_game
  claude mcp add dota2-mcp --scope project -- node "C:\Users\Admin\Documents\project\mcp_test\dist\server.js"
  ```
  В проектах, где сервер не нужен, просто **не добавляй** его — там его не будет.
- **`--scope local` (по умолчанию):** сервер виден только тебе и только в текущем
  проекте (пишется в `~/.claude.json`, не коммитится). То же «точечное»
  подключение, но без шаринга с командой.
- **`--scope user` НЕ используй для этого** — это глобально во всех проектах
  (как раз то, чего ты хочешь избежать).

Активный аддон сервер определит сам из папки проекта (см. §1b и пример с
`rda_game`), так что одну и ту же команду можно выполнять в каждом нужном проекте
— сервер подхватит ассеты именно того аддона.

Управление: `claude mcp list` (что подключено), `claude mcp get dota2-mcp`,
`claude mcp remove dota2-mcp` (в нужном scope). Включать/выключать без удаления —
через `/mcp` внутри Claude Code.

> Если используешь раздаваемый zip-релиз — путь в команде будет
> `…\release\dota2-mcp\server.mjs` вместо `…\dist\server.js`.

## 1. Когда вышло обновление Dota 2

Что меняется при патче: содержимое VPK (новые/удалённые/переименованные ассеты),
иногда — Dota 2 API (новые функции/энумы). Сервер этого **не подхватывает на лету**
— индекс и граф зависимостей строятся в памяти/кэше при запуске.

### Минимум (ассеты — модели, партиклы, материалы, attachment'ы)
Достаточно **обновить индекс**. Два способа:

- **Без перезапуска:** вызвать инструмент **`reindex`** (просто попроси: «сделай
  reindex»). Он перечитывает VPK + активный аддон и в фоне пересобирает граф
  зависимостей под новый индекс. Через пару секунд `find_assets`/`refs_to`/
  `model_info` уже видят новые ассеты.
- **С перезапуском:** перезапусти Claude Code (или MCP-клиент) — при старте всё
  переиндексируется заново.

> Граф зависимостей кэшируется на диске и инвалидируется по «отпечатку» индекса
> (суммарный размер + число записей VPK). После патча отпечаток меняется → кэш
> graph автоматически устаревает и пересобирается. Принудительно сбросить кэш:
> удалить папку `%TEMP%\dota2-mcp\graph\`.

### Если обновился Dota 2 API (нужны точные новые сигнатуры функций/энумов)
Инструменты `api_*` читают готовые JSON-дампы из репозитория
`@moddota/dota-data`. Они не обновляются сами. Порядок:

1. Обнови репозиторий дампов (он у тебя в `C:\Users\Admin\Documents\dota\dota-data`):
   ```powershell
   cd C:\Users\Admin\Documents\dota\dota-data
   git pull
   ```
   Если своего дампа под новый патч ещё нет в апстриме — его можно сгенерировать
   из игры: `npm ci && npm run full-build` (запускает Dota и снимает дамп; см.
   README того репо). Обычно проще дождаться апдейта апстрима и сделать `git pull`.
2. Если используешь **раздаваемый** релиз (vendored-копия данных) — обнови её:
   ```powershell
   cd C:\Users\Admin\Documents\project\mcp_test
   npm run vendor-data    # перекопирует свежие JSON в vendor/dota-data
   npm run package        # пересоберёт release/dota2-mcp.zip
   ```
3. Перезапусти сервер (API-дампы грузятся при старте).

### Если изменилась структура установки (Dota переехала на другой диск)
Сервер сам ищет Dota через Steam `libraryfolders.vdf`. Если не нашёл — задай
путь явно: env `DOTA_PATH` = `…\dota 2 beta\game` (см. §3 регистрации).

## 1a. Авто-слежение за ассетами аддона (live watch)

Сервер следит за папкой активного аддона и держит индекс + граф в актуальном
состоянии, пока ты пересобираешь ассеты — без ручного `reindex` и без перезапуска.

- **Реагирует только на скомпилированные ассеты** (`*_c`: `vpcf_c`, `vmdl_c`,
  `vmat_c`, `vtex_c`, …). Папка **`scripts/` игнорируется** (Lua/KV/cfg — это не
  ассеты, меняются часто и в граф не входят), как и dotfiles/temp/превью.
- **Обновление инкрементальное и только по аддону:** пересчитываются лишь рёбра
  графа для изменившихся аддонных файлов; неизменная база Valve (~378k файлов)
  не пересканируется. Десятки мс на изменение.
- **Дебаунс** (по умолч. 400 мс): пачка записей от одной компиляции схлопывается
  в одно обновление.
- Удалил ассет-оверрайд аддона → путь автоматически «откатывается» на базовый
  VPK (или исчезает из индекса, если базового нет).

Управление: `ADDON_WATCH=0` — выключить; `ADDON_WATCH_DEBOUNCE_MS` — изменить
дебаунс. После `reindex` вотчер переподключается к новой папке сам.

> Если правки ассетов не подхватываются: проверь, что аддон вообще определился
> (`index_status.addons` непусто), что файл реально `_c`, и что он лежит под
> namespace-папкой аддона (`particles/`, `models/`, …), а не в `scripts/`.

## 2. Когда обновился декомпилятор (Source2Viewer-CLI)

Иногда новый формат `_c` парсится только новой версией ValveResourceFormat.

1. Скачай свежий `cli-windows-x64.zip` из релизов
   `github.com/ValveResourceFormat/ValveResourceFormat`, распакуй (например в
   `C:\Users\Admin\Documents\ValveResourceFormat\`).
2. Сервер сам найдёт его (порядок: env `S2V_CLI` → `vendor/Source2Viewer-CLI/` →
   dev-путь). Для раздаваемого релиза обнови vendored-копию:
   ```powershell
   npm run vendor-cli
   npm run package
   ```
3. Проверь версию: вызови `index_status` → поле `cli.version`.

> Флаги CLI Valve официально **не гарантирует стабильными** между версиями. Если
> после обновления CLI сломалась интроспекция (`model_info`/`decompile` вернули
> ошибку) — см. §5, проверка декомпилятора.

## 3. Как обновить сам сервер (после правок кода)

```powershell
cd C:\Users\Admin\Documents\project\mcp_test
npm install        # если менялись зависимости
npm run build      # tsc -> dist/   (ОБЯЗАТЕЛЬНО: сервер запускается из dist/)
```

Перерегистрация в Claude Code обычно **не нужна** — путь к `dist/server.js` не
меняется; достаточно перезапустить сессию, чтобы поднялся новый процесс сервера.

Пересобрать раздаваемый архив:
```powershell
npm run package    # bundle + vendor-cli + vendor-data + zip -> release/dota2-mcp.zip
```

### Регистрация в Claude Code (если ещё не сделана / переехал путь)
```powershell
claude mcp add dota2-mcp -- node "C:\Users\Admin\Documents\project\mcp_test\dist\server.js"
# проверить:
claude mcp list
# удалить/перерегистрировать:
claude mcp remove dota2-mcp
```
Либо проектный `.mcp.json` (Claude Code предложит подтвердить при открытии папки).

### Чек после обновления (быстрая верификация)
```powershell
npm run typecheck          # tsc --noEmit, должно быть без ошибок
npx tsx src/mcptest.ts     # M1/M2 round-trip
npx tsx src/m5test.ts      # API
npx tsx src/m6test.ts      # консоль
npx tsx src/releasetest.ts # упакованный server.mjs целиком (RELEASE PASS)
```

## 4. Первая команда при ЛЮБОЙ проблеме

Вызови **`index_status`** — это диагностический дашборд. Что смотреть:

| Поле | Норма | Если не так |
|---|---|---|
| `ready` | `true` | `false` → читай `error` (обычно не найдены VPK; задай `DOTA_PATH`) |
| `gameDir` | путь к `…\dota 2 beta\game` | неверный → задай `DOTA_PATH` |
| `archives` | `dota` ~371k, `core` ~1.4k | пусто → VPK не найдены/битые |
| `addons` | твой аддон (если открыт) | пусто, хотя аддон открыт → §5 «аддон не виден» |
| `cli.available` | `true` | `false` → декомпилятор не найден; задай `S2V_CLI` (см. §2) |
| `cli.version` | строка версии | пусто → CLI не запускается |
| `graph.built` | `true` (после warmup ~неск. сек) | долго `false` → смотри stderr-лог |
| `api.loaded` | `true` | `false` → не найдены dota-data JSON; задай `DOTA_DATA_PATH` |
| `console.exists` | `true` если игра писала лог | `false` → запусти Dota с `-condebug` |
| `activityLog.path` | путь к логу активности сервера | см. §4a |
| `watcher.active` | `true` если аддон отслеживается | `false` без аддона — норма |

## 4a. Лог активности сервера (узнать про ошибки постфактум)

Сервер ведёт **постоянный лог всех вызовов инструментов** — это и есть способ
узнать, была ли ошибка или инструмент вернул что-то не то во время работы.

- **Что пишется:** на каждый вызов одна строка JSON (JSONL): время, имя
  инструмента, (усечённые) аргументы, длительность `ms`, и флаг `isError`. Если
  обработчик бросил исключение — пишется `level:"error"` со стеком, а клиент
  получает аккуратную ошибку (а не падение). Также логируются `startup` и
  неожиданные краши (`uncaughtException`/`unhandledRejection`).
- **Где лежит:** по умолчанию `<корень проекта>\logs\dota2-mcp.log` (для релиза —
  рядом с `server.mjs`). Точный путь — в `index_status.activityLog.path`.
  Переопределить — env `LOG_FILE`. Выключить — `LOG=0`. Ротация при ~5 МБ (бэкап
  `.1`); порог — `LOG_MAX_BYTES`.
- **Как разобрать, не выходя из чата:** инструмент **`server_log`** — попроси
  «покажи server_log errorsOnly» или «последние вызовы tool=particle_info».
  Параметры: `limit`, `errorsOnly` (только ошибки), `tool` (фильтр по имени),
  `level`. Возвращает записи newest-first + путь к файлу.
- **Или глазами/скриптом** (JSONL легко грепать):
  ```powershell
  # все ошибки за сессию:
  Select-String -Path "$PWD\logs\dota2-mcp.log" -Pattern '"level":"error"'
  # последние 20 строк:
  Get-Content "$PWD\logs\dota2-mcp.log" -Tail 20
  ```
  Каждая строка — валидный JSON, так что можно `... | ConvertFrom-Json` или
  обработать любым парсером.

Типичный сценарий: «инструмент вернул пустоту/странность» → вызови `server_log`
с `tool=<имя>` → посмотри `isError`, `ms`, `error` и аргументы того вызова.

## 5. Частые проблемы и решения

**Сервер не виден в Claude Code / `/mcp` пуст.**
Проверь `claude mcp list`. Убедись, что собран `dist/` (`npm run build`) — сервер
стартует из `dist/server.js`. Перезапусти Claude Code. Логи сервера идут в
**stderr** (stdout занят JSON-RPC) — смотри их в логах MCP-клиента
(`%APPDATA%\Claude\logs\` у Desktop; в Claude Code — вывод процесса).

**`index_status.ready = false` / «No Dota 2 VPK found».**
Steam-автодетект не нашёл игру. Задай env при регистрации:
`claude mcp add dota2-mcp --env DOTA_PATH="D:\...\dota 2 beta\game" -- node "...\dist\server.js"`.

**Новые ассеты после патча не находятся.**
Вызови `reindex` (или перезапусти сервер). Если всё равно нет — сбрось graph-кэш:
удали `%TEMP%\dota2-mcp\graph\` и сделай `reindex`.

**Ассеты аддона не видны / виден не тот аддон.**
Индексируется ТОЛЬКО один активный аддон. Резолв: `ADDON_PATH` → `CLAUDE_PROJECT_DIR`
→ cwd. Если открыт не тот проект — задай явно `ADDON_PATH` = путь к проекту аддона
(или к его `…\game\dota_addons\<name>`). Проверь `index_status.addons` —
там `source`, `dir`, `via` (откуда взялся путь) и `count`. Помни: ассеты в аддоне
должны быть **скомпилированы** (`_c`), а `<project>/game` обычно симлинк на
`…\game\dota_addons\<name>` — это поддерживается.

**`model_info` вернул пустые attachment'ы / `decompile` ошибка / `cli.available=false`.**
Это декомпилятор. Проверь `index_status.cli`. Запусти вручную, чтобы увидеть
ошибку:
```powershell
& "C:\Users\Admin\Documents\ValveResourceFormat\Source2Viewer-CLI.exe" --version
```
Если CLI устарел под новый формат `_c` — обнови его (§2). Поиск по именам и
attachment-кэш работают и без CLI, но интроспекция/превью/экспорт — нет.

**`api_*` пусто / `api.loaded=false`.**
Не найдены JSON-дампы. Проверь, что существует либо `vendor/dota-data/`, либо
sibling-репозиторий `C:\Users\Admin\Documents\dota\dota-data\files`, либо задай
`DOTA_DATA_PATH`. После обновления данных — перезапусти сервер.

**`console_errors` пусто / `console.exists=false`.**
Игра не пишет лог. Запусти Dota с параметром запуска `-condebug` (Steam → свойства
игры → параметры запуска). Лог появится в `…\game\dota\console.log`. Путь можно
переопределить env `CONSOLE_LOG`. Помни: `console_errors` показывает ошибки
**с момента** курсора (по умолчанию — старт сервера); чтобы поймать ошибки своего
теста, вызови `console_mark` ПЕРЕД запуском игры/перезагрузкой скриптов, потом
`console_errors`.

**Первый `refs_from`/`refs_to` тормозит (несколько секунд).**
Это разовая сборка графа (~2–4 с), дальше мгновенно. Обычно граф уже прогрет в
фоне (warmup при старте). Принудительно прогреть: вызови `build_graph`.

**Высокое потребление памяти (~300 МБ).**
Норма: это in-memory индекс ~372k+ ассетов. Не утечка. Кэш декомпиляции эфемерный
(TTL 10 мин, env `VPK_CACHE_TTL_MS`).

**Декомпилированные файлы где-то копятся.**
Временные артефакты сами удаляются (`%TEMP%\dota2-mcp\`). Исключение — `export_model`:
он пишет НАСОВСЕМ в `%TEMP%\dota2-mcp\exports\` (или `EXPORT_DIR`). Чисти вручную
при необходимости.

## 6. Ручной запуск сервера для отладки

Сервер общается по stdio, поэтому «голый» запуск просто ждёт JSON-RPC на входе —
но stderr сразу покажет лог инициализации (загрузка VPK, аддон, ошибки):
```powershell
node dist/server.js        # Ctrl+C для выхода; смотри строки [dota2-mcp] в stderr
```
Полноценная проверка инструментов «как из клиента» — через тест-скрипты
(спавнят сервер и дёргают инструменты):
```powershell
npx tsx src/mcptest.ts        # базовый round-trip + образцы ответов
npx tsx src/addontest.ts      # с env ADDON_PATH="<путь к аддону>"
```
Сбросить всё кэшированное состояние (граф, temp, экспорты):
```powershell
Remove-Item -Recurse -Force "$env:TEMP\dota2-mcp"
```

## 7. Шпаргалка по env-переменным

Задаются при регистрации: `claude mcp add dota2-mcp --env KEY=VALUE ... -- node "...\dist\server.js"`.

| Переменная | Когда задавать |
|---|---|
| `DOTA_PATH` | Steam-автодетект не нашёл игру / Dota на другом диске. |
| `ADDON_PATH` | Явно указать активный аддон. |
| `S2V_CLI` | Декомпилятор лежит не в стандартном месте. |
| `DOTA_DATA_PATH` | JSON-дампы API лежат не в vendor/sibling. |
| `CONSOLE_LOG` | Нестандартный путь к `console.log`. |
| `VPK_CACHE_TTL_MS` | Изменить TTL кэша декомпиляции (по умолч. 600000). |
| `EXPORT_DIR` | Куда `export_model` сохраняет glTF/GLB. |
| `ADDON_WATCH` | `0` — выключить авто-слежение за ассетами аддона. |
| `ADDON_WATCH_DEBOUNCE_MS` | Дебаунс вотчера в мс (по умолч. 400). |
| `LOG` | `0` — выключить лог активности. |
| `LOG_FILE` | Свой путь к файлу лога. |
| `LOG_MAX_BYTES` | Порог ротации лога (по умолч. 5 МБ). |
